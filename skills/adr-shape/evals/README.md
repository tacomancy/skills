# Evaluation fixtures

`evals.json` names each prompt, the fixture under `fixtures/` it runs against, and what to check. The rubrics assert on presence and routing — every rejected option with a reason, the deferral under *Deferred, deliberately* with a destination, versions and thresholds in the architecture document rather than the ADR, the drafted file passing `lint-adr.sh` — never on wording. For the review, they assert that the note names each departure and the destination of each reversible detail, and that it contains no rewritten ADR text. Run by hand with `skill-creator` before a merge that changes `SKILL.md`, and record the outcome in the pull request.

`trigger-evals.json` is the trigger set for the frontmatter description: queries that should reach the skill without naming it — an ADR to write, an ADR to review, whether a detail belongs in the ADR or the architecture document, a `grill-me` or `grill-with-docs` round closing with a decision — and near misses that should not — writing the architecture document itself, ranking a list by reversibility alone, scaffolding an ADR directory. Run it with `skill-creator`'s description evaluation before a merge that changes the description.
